# Sprout 产品方案（工作名）

> 从灵感到可验证交付：给点子特别多的人用的 AI 项目系统
> 版本 v0.1 · 2026-09 · 写作视角：VP Product

---

## 0. 一句话

**Sprout 把你随口说的点子接住，AI 把它整理成一棵分层的目标树，再调度不同的 AI agent（Claude Code、Codex 等）一个节点一个节点地做出来。每完成一个节点都附一份可以检查的 demo，每一笔钱都要经过你批准。**

它由三个产品层组成，要分开看，因为难度和风险完全不同：

| 层 | 用户价值 | 难度 | 同类产品 |
|---|---|---|---|
| **A. 捕捉**（Capture） | 点子不再丢 | 低 | Apple 备忘录、Otter、Mem、Tana |
| **B. 结构化**（Shape） | 模糊的点子变成清楚的目标和计划 | 中 | ChatGPT 对话、Notion AI、Taskade |
| **C. 执行与治理**（Build & Govern） | AI 真的把东西做出来，而且进度、花费、质量都看得见 | 高 | Devin、Codex cloud、Cursor 后台 agent、Replit Agent、Lovable |

**我们的差异不在任何单独一层，而在 A→B→C 连成一条线，并且 C 层是“证据驱动 + 预算治理”的。** 竞品要么只管记（A），要么只管写代码（C），没有一家从“我刚想到一个东西”一直负责到“这是能跑的 demo，花了 $12.40”。

| R4 | 不清楚的地方跟用户确认 | **澄清循环**：AI 带着默认假设提问，问题集中成一批，可以晚点回答 | P0 |

| R10 | 直观看到进度、卡在哪 | **项目仪表盘**：完成度、阻塞节点及原因、正在跑的任务 | P0 |

| R12 | estimated time，还需要花多少钱 | **预测**：剩余成本和时间给区间和置信度，不只给一个数 | P1 |
| R13 | 用户 approve 要不要自动继续开发 | **审批闸门 + 自动驾驶等级**：每步都问 / 预算内自动 / 全自动但有上限 | P0 |
| R14 | 每个节点完成后要有 demo（截图、功能 demo、测试） | **完成证据**：每个节点在开始前就定好验收标准和证据类型，完成后附上证据，由用户验收 | P0 |

## 2. 这到底是什么产品？（定位）

### 2.1 品类判断

它**不是**项目管理工具。Jira、Linear 管的是“一群人之间的工作分配”，而这里的执行者是 AI，管理者只有一个人。

更准确的说法是：**一个人 + 一群 AI agent 的“产品经理工作台”**。用户扮演 CEO 或产品负责人：出点子、做决定、验收、批预算。AI 扮演 PM（拆解、澄清、排期）和工程团队（执行）。

### 2.2 目标用户：先收窄

“P 人”描述的是性格，还不是市场。我建议按下面的顺序切入：

1. **滩头用户（MVP）：P 型独立开发者、indie hacker、会写一点代码的产品人**
   - 点子多，side project 坟场很大
   - 已经在用或愿意用 Claude Code、Codex，也有 API key
   - 愿意为“帮我把东西做完”付费（$20–50/月 + 用量）
2. **第二圈：不会写代码但想做工具的人**（创业者、设计师、PM）
   - 需要更多托管：云端沙盒、一键部署，不用自己配 API key
3. **第三圈：非软件类项目**（内容、活动、研究）
   - demo 的形式完全不同，**MVP 不做**，只支持捕捉和规划

### 2.3 核心洞察

P 人的问题**不只是忘**，更多是**半途而废**：新点子的多巴胺赢过老项目的执行成本。所以产品有两个隐藏任务：

- **降低“继续”的成本**：打开 app 看到的第一件事是“AI 昨晚做完了 3 个节点，这是 demo，要继续吗？”，不是一张待办清单。
- **保护专注，但不说教**：新点子会先被判断“属于哪个已有项目”，而不是默认开一个新项目。同时进行的项目数有软性提醒（比如“你现在有 4 个项目在跑，本月预算已用 70%”）。

### 2.4 北极星指标

**每周“已验收节点”数（Verified Nodes / Week）**：用户看过 demo 并点了“通过”的节点。

它同时衡量三件事：AI 真的做出了东西，东西质量过关，用户还在参与。辅助指标：
- 点子 → 第一个已验收节点的转化率和耗时
- 每个已验收节点的平均成本
- 预测成本和实际成本的偏差（衡量预测是否可信）
- 第 4 周留存

## 3. 没想清楚的地方（最重要的一节）

下面按“不解决就做不下去”的程度排序。每条都给了我的建议默认值，需要你拍板。

### 3.1 代码在哪里跑？谁的仓库？谁的钥匙？ 🔴 阻塞级

“AI 自动开发”需要一个执行环境。几种方案：

| 方案 | 优点 | 缺点 |
|---|---|---|
| a. 云端沙盒 + 用户的 GitHub 仓库 | 可以后台跑，手机也能驱动 | 我们要付基础设施成本，还有安全责任 |
| b. 用户本机跑（桌面 companion） | 便宜，代码不离开本机 | 电脑必须开着，手机端体验打折 |
| c. 直接用 Codex cloud、Claude Code 远程会话等现成托管环境 | 不用自建沙盒 | 依赖第三方，成本和状态不一定拿得到 |

**建议**：MVP 用 **a + c 的混合**：代码一律放在用户自己的 GitHub 仓库（仓库是唯一的事实来源），执行优先调用各家的托管 agent 环境，我们只做编排层。

### 3.2 成本数据拿不拿得到？ 🔴 阻塞级

需求里的“花了多少 token、多少钱”有个隐藏前提：

- **按量付费的 API**（BYOK）：token 数可以精确统计，钱可以算出来 ✅
- **订阅制工具**（比如 Claude Max 订阅下的 Claude Code、ChatGPT Plus 下的 Codex）：通常拿不到可靠的逐次成本，只能显示“用了多少额度 / 跑了多久” ⚠️

**建议**：
- 账本统一记三个量：`token`、`$`（能算时才显示）、`agent 运行时长`
- 界面上明确标出“估算”还是“实计”
- MVP 以 API key 接入为主，订阅制 agent 作为“不计费但计时”的连接器

### 3.3 “节点完成”由谁判定？ 🔴 阻塞级

AI 自己说“做完了”并不可信。需要定义 **Definition of Done**：

- 每个叶子节点在**开始执行前**就写好 2–5 条**验收标准**（AI 起草，用户可以改）
- 每条标准绑定一种**证据类型**：
  - `test`：自动化测试，看通过数和覆盖到的标准
  - `screenshot`：UI 截图（可以自动用 Playwright 跑）
  - `demo`：可交互的预览链接或录屏
  - `doc`：规划或调研类节点，产出一份文档
- 节点状态分成两步：**AI 完成 → 待验收 → 用户通过**。只有用户通过才算进度。
- 用户说“不行”要打回，打回原因会写进项目记忆，避免同样的错误再犯

### 3.4 澄清问题问多少、什么时候问？ 🟡 体验级

问太多，P 人会跑掉；问太少，AI 会做错。

**建议规则**：
- AI 先按**合理默认值**生成完整的目标树，把不确定的地方标成“假设”，而不是停下来等回答
- 只有会**改变结构或花钱方向**的问题才打断用户，一次最多 3 个，做成单选或多选（尽量不需要打字）
- 其余问题挂在对应节点上（黄色标记），执行到那个节点之前再问
- 没回答的问题会**阻塞相关节点**，但不会阻塞整个项目

### 3.5 新点子到底进哪里？ 🟡 体验级

一天好几个点子，如果每个都开一个项目，一周后首页就是一片坟场。

**建议**：所有输入先进**灵感收集箱（Inbox）**，AI 给出分流建议：
1. 属于已有项目的某个节点 → 挂上去，作为补充或新子节点
2. 是一个新项目 → 进入“孵化”（只生成计划，不自动执行，也不花钱）
3. 太模糊或只是一句感想 → 留在收集箱，AI 每周汇总一次（“你这周提了 3 次跟宠物有关的点子”）

用户点一下确认或改选，不需要自己整理。

### 3.6 分层到底分几层？每层是什么？ 🟡 需要定义

“level by level”需要一个固定的语义，否则每个项目的树长得都不一样，AI 也不知道该拆到哪里为止。

**建议固定为 4 层**：

| 层级 | 名称 | 定义 | 例子 |
|---|---|---|---|
| L0 | 愿景 Vision | 一句话：为谁解决什么问题 | 让养猫家庭一起记录和提醒喂食 |
| L1 | 里程碑 Milestone | 用户能感知到的能力，可以单独演示 | 家庭成员可以共享记录 |
| L2 | 功能 Feature | 一个完整的功能切片 | 实时同步 |
| L3 | 任务 Task | 一个 agent 一次能完成的工作，要有验收标准 | 用 Supabase Realtime 订阅 feeding 表 |

只有 L3 节点会被执行，L1 和 L2 的进度由下面的节点汇总得出。

### 3.7 项目上下文怎么在不同 agent 之间传递？ 🟡 架构级

Claude Code 和 Codex 各有各的会话记忆，互相看不到。如果一个项目混用多个 agent，上下文就会断。

**建议**：Sprout 维护一份**标准的项目上下文包（Project Context Pack）**，每次派任务时注入：
- `BRIEF.md`：愿景、用户、范围、不做什么
- `DECISIONS.md`：关键决策记录，包括用户的澄清回答和打回原因
- `TREE.json`：目标树和当前节点的验收标准
- 代码仓库本身，外加仓库里的 `CLAUDE.md`、`AGENTS.md` 等 agent 说明文件

也就是说，**仓库 + 上下文包是唯一的事实来源**，agent 可以随时替换。这样也顺便解决了“换模型”的问题。

### 3.8 自动选模型按什么选？ 🟢 可以后置

**建议**：先提供三种策略预设，而不是一个黑盒：
- **省钱**：规划用中档模型，写代码用便宜的模型，失败两次再升级
- **均衡**（默认）：按任务类型走一张默认路由表
- **质量优先**：全部用最强的模型

路由结果一定要可解释（“这个节点用 Sonnet，因为它是改 CRUD，历史上成功率 94%”），并且可以手动覆盖。

### 3.9 预测准不准？ 🟢 可以后置，但要诚实

新项目没有历史数据，预测一定不准。**建议**：
- 永远显示**区间**（$22–31），不显示单个数字
- 标出置信度，并随着已完成节点的增多逐渐收窄
- 把“预测偏差”作为内部指标持续校准

### 3.10 审批的粒度 🟡 体验级

“每一步都要 approve”会让人烦死，“全自动”又会让人不放心。**建议用“自动驾驶等级”，按项目设置**：

| 等级 | 行为 |
|---|---|
| L0 手动 | 每个节点开始前都要批准 |
| L1 批次（默认） | 批准一批节点和一个预算上限，批内自动执行 |
| L2 预算内自动 | 在项目月度预算内自动推进，超过预算或遇到风险操作（删数据、付费服务、部署生产环境）时再问 |

**风险操作永远要人工批准，不受等级影响。**

### 3.11 iOS 和网页各做什么？ 🟢 范围级

不要做功能完全对等的两个 app。**建议**：
- **iOS = 遥控器**：捕捉（语音优先、锁屏小组件、Action Button、Share Sheet）、审批、看 demo 验收、回答澄清问题、推送通知
- **网页 = 驾驶舱**：目标树编辑、上下文管理、模型路由、成本分析、深度 review

### 3.12 其他需要尽早想的

- **隐私**：语音原始录音存多久？代码会不会被用于训练？（建议：录音转写后 30 天删除，可以设置）
- **失败处理**：agent 连续失败 N 次后怎么办？（建议：自动暂停这个节点，标记为“卡住”，给出失败摘要和 2–3 个建议选项）
- **协作**：MVP 是单人产品，多人协作放到 V2
- **商业模式**：见 §7

## 4. 核心概念模型

```
Workspace
 ├─ Inbox（灵感收集箱）
 │   └─ Idea { 原文, 录音, 转写, AI 分流建议, 状态 }
 └─ Project
     ├─ Context Pack { brief, decisions[], glossary, repo }
     ├─ Goal Tree
     │   └─ Node { level L0–L3, 标题, 状态, 验收标准[], 证据[],
     │             指派模型/agent, 预估成本区间, 预估时间, 实际成本, 澄清问题[] }
     ├─ Runs（执行记录）{ node, agent, model, tokens, $, 时长, 日志, 结果 }
     ├─ Approvals（审批）{ 批次节点[], 预算上限, 状态 }
     ├─ Routing Policy { 策略预设, 任务类型 → 模型 }
     └─ Budget { 月度上限, 已用, 预测 }
```

### 4.1 节点状态机

```
草稿 ──(澄清完成)──▶ 就绪 ──(批准)──▶ 排队 ──▶ 执行中 ──▶ 待验收 ──(通过)──▶ 已完成
  │                                          │           │
  └─(有未回答的问题)─▶ 待澄清                 │           └─(打回)──▶ 就绪（带上反馈）
                                             └─(失败 N 次 / 超预算)──▶ 卡住
```

“卡在哪”只有 4 种原因，界面上要明确显示是哪一种：
1. **等你回答**（待澄清）
2. **等你批准**（审批闸门）
3. **等你验收**（待验收）
4. **AI 卡住**（失败、超预算、外部依赖）

前 3 种都是“球在用户手上”，这是 P 人产品最关键的一个视图：**首页先告诉你“有 5 件事等你，大概需要 2 分钟”。**

## 5. 关键用户流程

### 流程 1：捕捉 → 分流（10 秒）
1. iOS 长按 Action Button 或在锁屏小组件上开始说话
2. 转写，AI 清理并提取要点
3. AI 给出分流建议：“看起来是『宠物喂食 App』的新功能 → 挂到 3.2 喂食时间预测？”
4. 用户点确认；或者什么都不做，点子会留在收集箱

### 流程 2：点子 → 项目（2–5 分钟）
1. 在收集箱里把点子“升级为项目”
2. AI 先问最多 3 个关键问题（单选），比如平台、目标用户、MVP 范围
3. 生成 L0–L2 的目标树，其中假设的地方高亮显示
4. 用户可以直接编辑，或者选中节点给 AI 指令
5. 确认后项目进入“孵化完成”状态，给出总预算和工期估算区间

### 流程 3：批准 → 执行 → 验收（持续）
1. 系统推荐下一批节点，标出预计成本和时间
2. 用户批准（或调整范围、预算）
3. Agent 执行，过程中实时更新成本
4. 节点完成后推送：“2.2 实时同步 已完成 · 测试 18/18 通过 · $3.20 · 看 demo”
5. 用户在手机上看截图或测试结果，点通过或打回

### 流程 4：节点级调整
1. 在目标树中选中一个节点
2. 选择快捷指令（拆细 / 换方案 / 降低成本 / 不做了），或者直接输入
3. AI 返回修改建议的 diff（新增、删除、修改了哪些节点，成本变化多少）
4. 用户接受或拒绝，结果写入决策记录

## 6. 路线图

### MVP（第 0–10 周）：证明“点子 → 可验收的 demo”这条路走得通
- iOS 和网页的捕捉（文字 + 语音），收集箱加 AI 分流
- 点子 → 澄清 → 目标树（L0–L3），可以编辑，支持节点级 AI 指令
- 项目上下文包
- **只接 1 个执行 agent**（建议 Claude Code，通过 Agent SDK 在云端沙盒执行，代码推到用户的 GitHub）
- 验收标准 + 测试和截图两种证据
- 成本账本（token、$、时长），审批闸门（L0 和 L1 两个等级）
- 进度仪表盘，“等你处理”队列
- iOS：捕捉、审批、验收、推送

**不做**：多 agent、自动路由、非软件项目、协作、L2 自动驾驶

### V1（第 10–20 周）：多模型与治理
- 接入 Codex 等更多 agent，按任务类型路由，提供 3 种策略预设
- 预测区间和校准
- L2 预算内自动，风险操作拦截
- 证据加上可交互的 demo 预览链接和录屏
- 收集箱每周汇总

### V2（20 周以后）：扩圈
- 不会写代码的用户：一键模板、托管部署
- 非软件项目（内容、调研），证据类型为文档
- 协作：邀请别人来验收或评论
- 项目模板和社区市场

## 7. 商业模式

- **免费版**：无限捕捉，1 个活跃项目，只做规划不做执行
- **Pro（$20/月）**：不限项目，执行功能，自带 API key（BYOK），成本透明
- **Pro+ 用量**：使用平台托管的模型额度，按成本加价 10–20%，适合不想配置 API key 的第二圈用户
- 目标毛利来自订阅，用量部分只做薄利，这样“成本透明”这个卖点才站得住

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Agent 产出质量不稳定，demo 经常不过 | 核心价值崩塌 | 节点拆得足够小（L3 控制在 agent 一次能完成的范围）；打回时自动带上反馈；连续失败就暂停 |
| 大厂（OpenAI、Anthropic、GitHub）自己做编排层 | 被吃掉 | 差异放在捕捉、结构化和跨 agent 治理上；保持 agent 中立 |
| 成本失控，用户收到天价账单 | 信任崩塌 | 硬性预算上限，默认 L1 批次审批，超预算自动暂停 |
| 用户只捕捉不执行 | 不付费 | 免费版就展示“这个点子做出来大约要 $15 和 2 小时”，降低开始的门槛 |
| 安全：agent 误删数据、泄露密钥 | 严重事故 | 沙盒隔离、密钥托管、风险操作强制人工批准、全量审计日志 |

## 9. 需要你拍板的决策清单

1. 滩头用户是否确定为“P 型独立开发者”？（建议：是）
2. MVP 接哪一个 agent？（建议：Claude Code）
3. 执行环境：云端沙盒还是用户本机？（建议：云端 + 用户的 GitHub）
4. 节点是否固定 4 层？（建议：是，L0–L3）
5. 默认自动驾驶等级？（建议：L1 批次审批）
6. 非软件项目是否推到 V2？（建议：是）
7. 定价是否采用 BYOK 优先？（建议：是）

## 附：交互 Demo

`prototype/index.html` 是一个可以点击的原型，覆盖：
- 灵感收集箱：打字或模拟语音输入，看 AI 分流建议
- 目标树：分层展开，选中节点查看验收标准和证据，给 AI 发节点级指令并接受或拒绝 diff
- 澄清问题：回答后节点解除阻塞
- 审批闸门：批准下一批节点、切换自动驾驶等级
- 进度与花费：成本曲线、按模型拆分、剩余预测
- 模型路由：按任务类型指定模型或自动选择
- iOS 预览：捕捉、待处理事项、验收三个手机界面
